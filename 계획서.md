# Software Architecture & Implementation Plan

## 1. Executive Summary & Goals

Build a self-hosted, web-based mobile terminal that replicates the full feature set of Windows Terminal, running inside a Termux environment on Android. The terminal is accessed exclusively from the device's own browser at `http://localhost:8080` (localhost-only, no LAN exposure).

Primary goals:
- Provide a stable, full-featured terminal experience on Android Chrome, replacing the native Termux app as the primary shell interface.
- Guarantee session persistence: all terminal sessions survive server restarts and Termux app termination, living until explicitly killed by the user.
- Implement Windows Terminal parity: tabs, split panes, profiles, color schemes, themes, keybindings, command palette, search, copy/paste, hyperlinks, and mobile-specific touch controls.
- Auto-start the server whenever Termux runs (via `.bashrc` hook), with optional Termux:Boot support.
- Use `bash` as the default shell with `.bashrc` loaded automatically (interactive TTY).

## 2. Technical Stack & Rationale

| Component | Choice | Rationale |
|---|---|---|
| Runtime | Node.js v26.4.0 (already installed) | Single language across server and tooling; npm ecosystem |
| PTY backend | `node-pty` 1.1.0 | Verified: compiles from source and spawns PTY successfully on this Termux (aarch64) |
| HTTP server | `express` | Static file serving + small REST API |
| WebSocket | `ws` | Bidirectional PTY data transport |
| Session persistence | `tmux` 3.7c (already installed) | Sessions survive server/process death; re-attach via `tmux new-session -A` |
| Terminal renderer | `xterm.js` 5.3.0 | Industry-standard web terminal; full VT/xterm emulation |
| Addons | `@xterm/addon-fit`, `-search`, `-webgl`, `-unicode11`, `-serialize`, `-ligatures`, `-unicode-graphemes` | Fit/resize, search, GPU rendering, Unicode/emoji, buffer export, font ligatures |
| Frontend assets | Vendored locally under `public/vendor/` | No CDN dependency; works offline on localhost |
| Shell | `bash` (interactive) | Default profile; sources `.bashrc` automatically on TTY attach |

Rejected alternatives:
- `ttyd` (installed): single-terminal only; no tabs/panes/profiles; insufficient for Windows Terminal parity.
- `gotty`: same limitation.
- Python backend (`pyte` + `websockets`): viable but weaker PTY fidelity and ecosystem for terminal features.

## 4. Architecture & Data Flow

```text
Android Chrome (mobile browser)
        │  WebSocket (ws://localhost:8080/ws)
        ▼
Node.js server (express + ws)
        │  node-pty (forkpty)
        ▼
tmux session (tw-<uuid>)  ──►  bash (interactive, sources .bashrc)
```

Session lifecycle:
1. Client requests session creation (profile id) via REST or WS `create`.
2. Server spawns `node-pty` with command `tmux -f server/tmux.conf new-session -A -s tw-<uuid> -x <cols> -y <rows> <shell>`.
3. If the tmux session already exists, `-A` re-attaches (persistence across reconnects).
4. PTY output streams to client as WS `output`; client input streams as WS `input`.
5. On WS disconnect: PTY process exits, tmux detaches, session survives.
6. On user close/kill: server runs `tmux kill-session -t tw-<uuid>` — permanent termination.

WebSocket protocol:
- Client → Server: `{type:"input", data}`, `{type:"resize", cols, rows}`, `{type:"create", profileId}`, `{type:"close"}`, `{type:"kill"}`
- Server → Client: `{type:"output", data}`, `{type:"exit", code}`, `{type:"title", title}`

REST API:
- `GET /api/sessions` — list live tmux sessions
- `POST /api/sessions` — create session from profile
- `DELETE /api/sessions/:id` — kill session
- `GET /api/settings` / `PUT /api/settings` — read/write settings.json
- `GET /api/profiles` — resolved profile list

tmux configuration (`server/tmux.conf`):
- `set -g history-limit 0` — scrollback handled by xterm.js (avoids dual-scrollback conflict)
- `set -g status off` — UI chrome provided by web app
- `set -g mouse on` — mouse mode passthrough
- `set -g escape-time 10` — responsive Alt/Esc sequences
- `set -g default-terminal "xterm-256color"`

## 5. Feature Specification (Windows Terminal Parity)

1. **Tabs** — create, close, rename, title sync via OSC 0/2, active-tab highlight.
2. **Split panes** — horizontal/vertical split, drag-to-resize dividers, focus navigation (Alt+arrows), close pane.
3. **Profiles** — bash (default), zsh, python, ssh, custom commands; per-profile: name, emoji icon, command, cwd, env vars, color scheme, font size, background.
4. **Color schemes** — Windows Terminal built-ins (Campbell, Campbell Powershell, One Half Dark/Light, Solarized Dark/Light, Tango Dark/Light, Vintage, Dracula) + custom schemes in settings.json.
5. **Themes** — dark/light/system modes; custom JSON: background color/image, opacity, acrylic blur (backdrop-filter), accent color, tab styling.
6. **Fonts** — family, size, line height, letter spacing, ligatures toggle, cursor style (block/bar/underline), cursor blink.
7. **Copy/paste** — Ctrl+Shift+C/V, right-click paste, OSC 52 clipboard, auto-copy on selection.
8. **Search** — Ctrl+Shift+F; regex, case sensitivity, whole-word, highlight all, next/previous.
9. **Command palette** — Ctrl+Shift+P; fuzzy search over actions (new tab, split, change scheme, toggle theme, etc.).
10. **Keybindings** — WT-style chord JSON (`"ctrl+shift+t"`), defaults + user overrides.
11. **Scrollback** — configurable, default 10000 lines (xterm.js).
12. **Mouse** — wheel scroll, selection, application mouse mode passthrough.
13. **Hyperlinks** — OSC 8, clickable, hover underline.
14. **Bell** — visual flash + optional audio.
15. **Background** — solid color, image URL, opacity/acrylic blur.
16. **Unicode** — unicode11 + graphemes addons (emoji, CJK, combining chars).
17. **Buffer export** — serialize addon (save session text to file/clipboard).
18. **Session persistence** — tmux backend, auto-reconnect on WS drop, session list/re-attach UI.
19. **Mobile (Android Chrome)** — on-screen touch bar (Ctrl/Alt/Esc/Tab/arrows/F-keys), pinch zoom, keyboard avoidance (visualViewport), tap-to-focus, long-press paste, touch scrolling.
20. **Settings UI** — GUI panel + raw JSON editor, live apply, persisted to settings.json.

## 8. Auto-Start & Operations

- `start.sh` — idempotent: checks pid file/port, starts `node server/index.js` with nohup, logs to `~/.terminalweb/server.log`.
- `stop.sh` — kills server process (sessions survive via tmux).
- `.bashrc` hook (appended during install):
  ```bash
  [ -f ~/projects/terminalweb/start.sh ] && ~/projects/terminalweb/start.sh
  ```
- Optional Termux:Boot: `~/.termux/boot/terminalweb.sh` calling `start.sh` for device-boot startup.
- Access URL: `http://localhost:8080` in Android Chrome.

## 9. Security

- Server binds `127.0.0.1` only — no LAN exposure.
- Optional `token` in settings.json: when set, first visit prompts for token (sessionStorage), WS authenticated via query parameter. Disabled by default.

## 10. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| node-pty native build failure | Already verified compiling and spawning on this device (aarch64) |
| WebGL renderer unsupported on mobile | Automatic fallback to canvas/DOM renderer |
| tmux vs xterm.js scrollback conflict | tmux `history-limit 0`; xterm.js owns scrollback (buffer resets on reconnect — accepted) |
| Android keyboard viewport issues | visualViewport API + keyboard avoidance handling |
| Ligature font unavailable | Ligatures toggle; falls back to monospace |
| tmux session name collisions | UUID-based session ids (`tw-<uuid>`) |

## 11. Definition of Done

- Server starts via `start.sh`; terminal reachable at `http://localhost:8080`.
- Full Windows Terminal feature list (Section 5) functional on Android Chrome.
- Sessions persist across server restart and Termux app kill; kill only via explicit user action.
- `.bashrc` auto-start works; server restarts idempotently.
- All frontend assets served locally (no CDN).
